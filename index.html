Quick Start

This tool runs all 15 statistical tests defined in NIST SP 800-22 Rev 1a on a binary sequence. Each test produces a p-value. A p-value below α = 0.01 indicates evidence of non-randomness.

Three steps: ① Load a sequence (file, paste, or generate) → ② Adjust parameters if needed → ③ Click Run All Tests

Step 1 — Provide a sequence

Three input methods are available:

  • File drop / browse — drag any file onto the drop zone or click it to open a file picker. The format is detected automatically (see Supported File Formats below).
  • Paste — type or paste a string of 0s and 1s directly into the text area. Spaces, tabs, and newlines are ignored.
  • Generate — click 1 000 bits or 10 000 bits to fill the text area with a pseudo-random sequence for demonstration.

Minimum length: 100 bits. NIST recommends at least 1 000 bits. Tests 14 & 15 require ≈ 500 000+ bits in practice (\( J \ge 500 \) zero crossings; expected \( \mathbb{E}[J] \approx \sqrt{2n/\pi} \)).

Step 2 — Parameters (optional)

Three numeric inputs control specific tests. Default values follow NIST recommendations and work well for most inputs — see the Parameters section below for details.

Step 3 — Navigate results

After clicking Run All Tests, the sidebar shows all 15 tests with colour-coded indicator dots. Click any test to slide its detailed view into the right panel — you will see the p-value, key statistics, and a chart. The summary strip at the top counts PASS / FAIL / N/A across all tests.

Supported File Formats

Any file can be loaded. The pipeline detects the correct decoding mode in this order:

FormatDetectionHow it is decoded
Binary file Extension: .bin .exe .jpg .pdf .gz .zip and others Read as raw bytes via ArrayBuffer. Each byte expands to 8 bits, MSB first. Never interpreted as text.
Plain 0/1 text File content contains only the characters 0 and 1 (whitespace ignored) Used directly as a bit string. Spaces and line breaks are stripped.
Base64-encoded Content matches the Base64 character set [A-Za-z0-9+/=] after whitespace removal Decoded to raw bytes via atob() first, then each byte → 8 bits. Base64 characters are never analysed directly as bits.

Parameters

ParameterDefaultRangeDescription
Block M1288 – 10 000 Test 2 (Block Frequency). Size of each block in bits. The proportion of 1s per block should be ≈ 0.5 for a random sequence. NIST recommends \( M \ge 20 \) and at least 100 complete blocks, so the sequence should contain ≥ \( 100 \times M \) bits.
Template m92 – 10 Tests 7 & 8. Length of the bit pattern searched for. Test 7 (Non-Overlapping) uses the aperiodic pattern 0…01 and advances the window by m after each match. Test 8 (Overlapping) uses the all-ones pattern 1…1 with a sliding window of step 1.
LC block50050 – 5 000 Test 9 (Linear Complexity). Block length for Berlekamp–Massey analysis. Each block is tested independently. NIST recommends \( 500 \le M \le 5\,000 \). Smaller values increase block count but reduce sensitivity; larger values detect longer linear structure.

Reading Results

Status badges

PASS (green) — \( p\text{-value} \ge 0.01 \). No statistical evidence of non-randomness at the 1% significance level.
FAIL (red) — \( p\text{-value} < 0.01 \). The sequence exhibits a pattern this test is sensitive to.
N/A (grey) — The sequence is too short to run this test. The panel shows the exact minimum required.

Multiple p-values

Test 11 (Serial) reports two p-values. Tests 14 and 15 report one p-value per state (\( \pm 1 \dots \pm 4 \) and \( \pm 1 \dots \pm 9 \) respectively). The overall PASS/FAIL badge for these tests uses the minimum p-value across all states — the most conservative approach.

How conclusive is a failure?

For any truly random sequence, approximately 1 in 100 tests will fail at \( \alpha = 0.01 \) purely by chance. A single isolated failure is not conclusive. Consistent failures across multiple tests — especially Tests 1, 2, or 3 — or a p-value extremely close to 0 carry significantly more weight.

p-value very close to 1.0

An unusually high p-value (e.g. > 0.9999) can also signal a problem: the sequence may be too perfectly balanced — for example a forced alternating 10101010… pattern. For genuinely random sequences, p-values are themselves uniformly distributed over [0, 1].

Limitations of this tool

NIST SP 800-22 Section 4 recommends testing at least 55 sequences of 1 000 000 bits each for a formal generator evaluation. This tool analyses a single sequence at a time, which is sufficient for a quick check but not for a rigorous certification.

Architecture & Vision

Statistical randomness testing is a foundational requirement in cryptography, but traditional tools are often cumbersome, requiring complex CLI setups or backend servers. This project brings the complete NIST SP 800-22 battery of tests directly into the browser.

Designed for security researchers, cryptographers, and educators, the application runs entirely client-side. This ensures zero latency, strict data privacy, and immediate visual feedback without ever transmitting sensitive bit sequences over a network. The built-in generator uses the browser's native cryptographically secure PRNG (window.crypto.getRandomValues()).

File Processing Pipeline

Any file can be loaded via drag-and-drop or the file picker. The pipeline determines the correct decoding mode automatically:

  • Binary files (.bin, .exe, .jpg, .pdf, .gz, …) — read as raw bytes; each byte expands to 8 bits, MSB first. Never interpreted as text.
  • Base64-encoded files — detected by character set; decoded to raw bytes via atob() first, then expanded to bits. Base64 characters are never analysed directly as bits.
  • Plain 0/1 text — used directly as a bit string. Whitespace and line breaks are stripped.
  • Unknown content — falls back to raw binary mode.

The byte-to-bit convention follows NIST: MSB first. Byte 0xAB (10101011₂) → 10101011.

Technical Limitations

  • Tests 14 & 15 need ≥ 500 000 bits in practice. The expected cycle count is \( \mathbb{E}[J] \approx \sqrt{2n/\pi} \): for \( n = 10\,000 \) this gives \( \mathbb{E}[J] \approx 80 \); for \( n = 500\,000 \) this gives \( \mathbb{E}[J] \approx 564 \).
  • Test 9 (Maurer) needs ≥ 904 960 bits for the minimum \( L=6 \) parameter level.
  • NIST SP 800-22 Section 4 recommends testing ≥ 55 sequences of 1 000 000 bits each for a formal generator evaluation. This tool analyses one sequence at a time.
